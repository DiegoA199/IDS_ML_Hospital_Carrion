1. Propósito del documento
El presente documento técnico describe la aplicación propuesta para el proyecto de investigación IDS-ML. Su finalidad es explicar, de manera formal y verificable, cómo el prototipo software se relaciona con el informe de tesis, qué módulos incluye, qué tecnologías utiliza y de qué manera puede ejecutarse en entorno local y en nube. Este documento complementa el informe principal y sirve como evidencia técnica de la solución propuesta.
La aplicación se plantea como un prototipo web de detección de intrusiones basado en machine learning. No reemplaza a una solución IDS empresarial instalada en producción; su propósito académico es demostrar la viabilidad de cargar datos de tráfico de red, preparar información, entrenar modelos, comparar métricas, seleccionar el mejor modelo, analizar tráfico nuevo, generar alertas y registrar evidencias funcionales para la investigación.
2. Descripción general de la aplicación
El prototipo IDS-ML está orientado al contexto del Hospital Regional Docente Clínico Quirúrgico Daniel Alcides Carrión. Su diseño responde a la necesidad de apoyar la identificación de amenazas en una red institucional hospitalaria mediante análisis de datos y modelos de machine learning. El sistema se desarrolla con Python y Streamlit para la interfaz, Scikit-learn para el entrenamiento de modelos, Pandas y NumPy para procesamiento de datos, Firebase/Firestore para almacenamiento cloud, SQLite como respaldo local y GitHub para control de versiones.

4. Arquitectura técnica del sistema
La arquitectura propuesta es modular por capas, con separación entre interfaz, lógica de aplicación, servicios de machine learning, repositorios de almacenamiento y despliegue. Esta separación permite mantener el prototipo ordenado, facilitar pruebas y evitar que los componentes de datos, modelos y visualización dependan directamente unos de otros.
Capa
Responsabilidad
Capa de presentación
Streamlit; contiene páginas, formularios, tablas, gráficos y navegación.
Capa de aplicación
Coordina casos de uso: cargar dataset, entrenar, evaluar, predecir, alertar y reportar.
Capa de servicios ML
Incluye preprocesamiento, entrenamiento, selección de características, métricas y persistencia de modelos.
Capa de repositorios
Implementa Repository Pattern para usar Firestore o SQLite sin cambiar la lógica principal.
Capa de persistencia
Firestore para nube y SQLite para respaldo local.
Capa de despliegue
GitHub, requirements.txt, Streamlit Cloud/Render y Docker opcional.
5. Especificación de funcionamiento en la nube
La aplicación puede considerarse parcialmente en nube porque combina dos componentes cloud principales: el despliegue web en Streamlit Cloud o Render y la persistencia de resultados en Firebase/Firestore. La interfaz del sistema puede ejecutarse desde una URL pública o privada de Streamlit Cloud/Render, mientras que los resultados, alertas, bitácoras y configuraciones pueden guardarse en Firestore. SQLite se mantiene como respaldo local para pruebas, continuidad y desarrollo.

6. Persistencia cloud y respaldo local
El patrón Repository Pattern permite cambiar el proveedor de almacenamiento sin alterar los módulos principales. Por ejemplo, el módulo de alertas no necesita saber si los datos se guardan en Firestore o SQLite; solo invoca una interfaz de repositorio. Esta decisión mejora mantenibilidad, trazabilidad y portabilidad.

7. Seguridad, roles y protección de secretos
La seguridad del prototipo se aborda como seguridad básica de aplicación académica. Se recomienda usar roles diferenciados, validación de entradas, protección de archivos de credenciales, control de acceso a páginas y exclusión de secretos del repositorio GitHub. El archivo .streamlit/secrets.toml, archivos JSON de Firebase, .env y credenciales no deben subirse al repositorio.

13. Limitaciones y condiciones de uso académico
El prototipo se desarrolla con fines académicos. Su evaluación inicial puede realizarse con datasets públicos de IDS o datos autorizados por la organización. No se debe ejecutar captura real de tráfico hospitalario sin autorización formal. Tampoco debe almacenarse información clínica, datos personales o credenciales institucionales dentro del prototipo. La aplicación sirve para demostrar el diseño, evaluación y utilidad de modelos IDS-ML, no para sustituir una solución de seguridad empresarial certificada.
